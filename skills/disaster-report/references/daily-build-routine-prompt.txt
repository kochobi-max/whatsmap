ADRC の大規模災害レポートについて、最新状況を確認し、イベントJSONを更新して
ビルドし、配布ブランチへ出してください。
イベントは名指ししません。`meta.status: "active"` の全件が対象です。

## 0. 最初にこれをやる（省略不可）

```bash
git fetch origin claude/workflow-automation-review-shyt35
git checkout claude/workflow-automation-review-shyt35
git pull origin claude/workflow-automation-review-shyt35
test -f skills/disaster-report/SKILL.md || echo "MISSING_SKILL"
```

`MISSING_SKILL` が出たら中断して、その旨だけ報告する。推測でファイルを作り直さない。

## 1. 手順は SKILL.md にある。そちらに従う

`skills/disaster-report/SKILL.md` を読む。**§1-1「収集の手順」** に並んでいる
7段を**最後まで**通す。§0-0（他のセッションの成果を先に探す）・§0（見送った災害の台帳）・
§0-1（災害の種別は動く）・§1-0（情報源に届くことを先に確かめる）も読むこと。

1. `scan_updates.js` — 未取り込みの資料（**0件は「無い」ではなく「取れていない」**）
2. 一次情報源を直接見る（`references/sources/<ISO3>.md`。ネパールは `fetch_ndrrma.js`）
3. **現地語の国内報道を当たる**（英語の国際情報源だけでは発表を取り落とす）
4. センチネルアジアの通知メールを読む（提供記録は**メールにしか無い**）
5. 進行中の警告を `active_warnings[]` に足す
6. `build_all.js` — 検証・ビルド・配布（**`publish_dist` を飛ばさない**）
7. やらないこと（**メールは送らない**／イベントを勝手に作らない／PDFはここで作りきる）

データを更新したらコミットして `claude/workflow-automation-review-shyt35` へプッシュする。
`_build/` はコミットしない。`dist` は `publish_dist.js` が扱うので手で push しない。
`fetch first` で弾かれたら `git pull --rebase` してから押し直す。

**このプロンプトと SKILL.md が食い違ったら、SKILL.md に従う。**
ここは入口だけを書いてある。詳細をここへ写さない（写すと古くなる）。

## 2. 報告（この5点を必ず書く）

1. `scan_updates.js` で未取り込みだった資料と、開いた結果（取り込んだ／関係なかった）
2. センチネルアジアのメールから拾った提供記録。無ければ「新しい提供記録なし」
3. `build_all.js` のまとめの表をそのまま
4. 動いた数値の一覧、または「一次情報に到達したうえで変化なし」
5. 許可リストへの追加が必要なドメイン、および `watchlist.js` が `NEW` / `RERAISE` を
   返した要請番号（`HOLD` は書かない）

途中で止まった場合は、どの段階で何が無くて止まったかを1行で書く。黙って終わらないこと。
