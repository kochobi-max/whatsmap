```bash
git fetch origin claude/workflow-automation-review-shyt35
git checkout claude/workflow-automation-review-shyt35
git pull origin claude/workflow-automation-review-shyt35
test -f skills/disaster-report/SKILL.md || echo "MISSING_SKILL"
```

`MISSING_SKILL` が出たら中断して、その旨だけ報告する。推測でファイルを作り直さない。

## 1. 手順は SKILL.md にある。そちらに従う

`skills/disaster-report/SKILL.md` の **§5-1-4「送信の手順」** を読み、
そこに並んでいる6段を**最後まで**通す。

1. `verify_published.js` — 公開の確認（**作り直して比べない。PDFは必ず不一致になる**）
2. `resolve_event.js --event <GLIDE>` — 数値急変ゲート（§2 / §2-0）
3. 送れるものを送る（§5-2。件名・本文・文体・参考映像はすべてそこ）
4. `warning_gate.js <GLIDE>` — **送れなかったものの進行中の警告だけ先に送る**（§5-1-2）
5. `check_pc_health.js` — **PCが2日以上止まっていれば荒木田さんへ知らせる**（§5-1-3）
6. `_prev` と `skills/disaster-report/_state/` をコミットして
   `claude/workflow-automation-review-shyt35` へプッシュ

**4と5を飛ばして終わらない。**
**このプロンプトと SKILL.md が食い違ったら、SKILL.md に従う。**
ここは入口だけを書いてある。詳細をここへ写さない（写すと古くなる）。

## 2. 報告

イベントごとに1行。

```
<GLIDE>  送信（delivered）／承認待ち／見送り（理由）／下書きで停止（理由）
```

そのあとに2行。

- 見送ったイベントの警告メール（送信（delivered）／進行中の警告なし／送信済み）
- PC稼働（正常／N日間停止・荒木田さんへ通知（delivered））

**1件も送らなかった日も黙って終わらない。** なぜ送らなかったかを必ず書く。
途中で止まった場合は、どの段階で何が無くて止まったかを1行で書く。
