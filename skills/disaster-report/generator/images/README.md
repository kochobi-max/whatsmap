# images — イベント別の画像

## なぜここに置くか

2026-08-19、熊本レポートのビルドで **ADRCロゴを含む27枚が消えた**。
旧版を作った環境（Cowork側のサンドボックス）にはあったが、OneDrive にも
リポジトリにも入っていなかった。**どこにも保存されていなかった。**
配布済みの pptx から取り出して復旧したが、それが唯一の手段だった。

同じことを繰り返さないため、画像を版管理下に置く。

## 構成

```
images/
  <GLIDE番号>/     イベント専用。ここに無いキーは共通フォルダへ落ちない
  adrc_logo.png    全イベント共通（と title_bg）だけが共通フォルダから拾われる
```

専用フォルダを持つイベントが共通フォルダへ落ちないのは `apply_image_isolation.js`
（13本目）による。落ちると **他の災害の画像を掴む**。実際、コロンビアが熊本の
震央分布図・市町村地図・発震機構・発動ページを拾っていた。
**違う画像が出るくらいなら、枠のままの方がよい。**

## 命名

`resolveImg()` の探索順は、各ディレクトリごとに次の3通り。

1. `<キー>_manual.png` / `.jpg` / `.jpeg` — 手で保存した版。最優先
2. イベントJSONの `images.<キー>` が指すファイル
3. `<キー>.png`

JPEG は `<キー>_manual.jpg` にする。`images.<キー>` が `null` のキーは
`<キー>.png` しか見ないため、JPEG はこの名前でないと拾われない。

## 欠けているものの確認

ビルドの最後に一覧が出る（`apply_image_report.js`、10本目）。

```
── 画像  解決 30 / 未解決 4
   ✓ adrc_logo               images/adrc_logo.png
   ✗ title_bg                （枠のみ）
```

**「ビルドが通った」は画像が入っている証明にならない。** 見つからなければ
点線の枠とプレースホルダ文言が描かれるだけで、例外は出ない。

## 共有画像は images/ 直下に置く

`adrc_logo` と `title_bg` は**全イベント共通**の素材で、画像分離パッチ
（`apply_image_isolation.js`）でも共有キーとして扱われ、イベント専用フォルダに
無ければ `images/` 直下へ落ちてくる。

ところが `adrc_logo.png` は熊本のフォルダの中にしか無く、共有の落ち先が空だった。
そのためコロンビアはロゴが枠のみで出ていた。**共有素材は `images/` 直下に置く。**
イベント専用フォルダの方が優先されるので、熊本の出力は変わらない。
