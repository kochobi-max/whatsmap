# 出張ドシエ — 収集・抽出層

`trip-report-creator`（書類を作る）と `trip-photo-slides`（写真をまとめる）の**前段**に立ち、
これまで人が口頭で入力していた内容を、既にある機械可読な入力から組み立てる。

**この業務が自動化の効果が最も大きい。** 理由は、Plaud録音・Calendar・領収書画像という
入力がすでに機械可読で揃っているのに、現在は人がそれを見ながら再入力しているため。

---

## 入力（フォルダに放り込むだけ）

| 置くもの | 使い道 | 必須 |
|---------|-------|------|
| 領収書（写真・PDF） | 費目・金額・日付 | 任意 |
| ボーディングパス（写真・PDF） | 区間・便名・搭乗日（交通費の裏づけ） | 任意 |
| 乗換案内スクショ | 国内経路と金額（精算書にそのまま貼付） | 任意 |
| 出張申請書（docx / pdf） | 出張者・期間・出張先・目的・Project | 推奨 |

**何も入れなくても Calendar と Plaud だけで骨格はできる。**

---

## 手順

### 1. 期間の確定

- 申請書があれば申請書を優先（`trip-report-creator` ステップ1と同じ抽出）
- なければ Google Calendar から出張期間・訪問先イベントを取得する
- 期間が確定できなければ**ここで人に聞く**。以降の全工程が期間に依存するため

### 2. 会議記録の収集（Plaud）

```
mcp__Plaud__list_files  --date_from <出張開始> --date_to <出張終了>
mcp__Plaud__get_note      各録音のAIノート（要約・アクションアイテム・トピック）
mcp__Plaud__get_transcript 話者つきの逐語（必要な録音のみ）
```

抽出するもの:

| 抽出 | 出力先 | 方法 |
|------|--------|------|
| 面会者（氏名・所属） | 報告書「Meeting with」 | 自己紹介発話（「〜の◯◯です」）と話者ラベルから |
| 日ごとの活動内容 | 報告書「Trip Report」 | 録音ごとの note を日付でまとめる |
| 決定事項・宿題 | フォローアップ用（報告書には入れない） | note の action items |

> **`get_transcript` は全録音に対して回さない。** まず `get_note` で足りるか判断し、
> 面会者の氏名確認や発言の帰属が必要な録音だけ逐語を取る。

### 3. 経費の抽出（OCR）

| 入力 | 読み取る項目 |
|------|------------|
| 領収書 | 日付・金額・通貨・支払先・費目（交通／宿泊／日当／その他） |
| ボーディングパス | 区間・便名・搭乗日・搭乗者名 |
| 乗換案内スクショ | 経路・金額・日付 |

- **金額は必ず原文の桁をそのまま記録する。** 丸めない、推定しない
- 海外の領収書は**通貨記号と桁区切りの流儀に注意**（欧州・中南米は `.` が桁区切り）
- 読み取れない項目は**空欄にして確信度「低」**とする。埋めてはいけない

### 4. 突合

- 経費の日付 × 行程の日付 が合うか
- ボーディングパスの区間 × 申請書の出張先 が合うか
- **合わないものだけを抽出**して確認シートに載せる

### 5. 生成

`trip-report-creator` の CLI へ JSON で流し込む（国内／海外を判定して振り分ける）。

```
出張報告書.docx  ＋  旅費精算書.xlsx
```

写真がある場合は `trip-photo-slides` へ連携する（**目視選定は従来どおり人**）。

## 🚦 確認シート（このスキルの肝・省略不可）

成果物と一緒に、**AIが埋めた欄だけの一覧**を出す。
人は報告書と精算書を読み直さず、**このシートだけを見ればよい**状態にする。

| 欄 | AIの記入値 | 根拠 | 確信度 |
|----|----------|------|--------|
| 面会者 | JICA関西 重吉氏 | Plaud 08-12 05:12「JICA関西の重吉です」 | 高 |
| 8/13の活動 | STEP5-6演習の講評 | Plaud 08-13 note | 中 |
| 交通費 15,500円 | 西荻窪〜灘 | 乗換案内スクショ IMG_0412 | 高 |
| 宿泊費 26,900円 | 3泊 | 領収書 PDF p.1 | 高 |
| 日当 1,600円×1日 | — | **根拠なし（AI推定）** | **低** |

### 確信度の定義

| 確信度 | 条件 |
|--------|------|
| **高** | 一次資料に明示（領収書の印字金額、逐語の自己紹介） |
| **中** | 一次資料から推論（noteの要約から活動内容を再構成） |
| **低** | 根拠なし。規程や慣行からの推定 |

> **確信度「低」の欄は空欄で出す。** 値を入れて「低」と書くと、人はそれを追認しがちになる。
> 空欄にして人に埋めさせるほうが安全（ユーザー決定・2026-08-17）。

## 自律度

**L2**（収集・抽出・生成まで自動、提出は必ず人）

| 人が必ず確認する点 | 理由 | なぜ機械に任せられないか |
|------------------|------|----------------------|
| **金額（全件）** | ①不可逆 ②数値責任 | 1円違えば経理差戻し。OCRは桁・通貨記号を誤る |
| **面会者の氏名・肩書** | ③人間関係 | 音声からの氏名認識は誤る。相手先に失礼が生じる |
| **発言の帰属** | ③人間関係 | 話者分離の誤りが報告書に載ると実害になる |
| **非公開情報の扱い** | ③人間関係 | 録音に含まれる人事・未確定案件を所内回覧文書に書けない |
| 日当・宿泊の規程適用 | ⑤新規判断 | ADRC規程の解釈は人 |

### 非公開情報の扱い（重要）

Plaudの録音には人事異動・未確定案件・第三者の評価が含まれる。
**報告書は所内回覧される**ので、録音の内容をそのまま書かない。

- 報告書に書くのは**業務上の活動と成果**のみ
- 人事・未確定案件・個人評価に触れる部分は**確認シートに「除外した」と明記**する
  （黙って落とすと、人が「AIが拾い漏らした」のか「意図的に外した」のか判別できない）

---

## 注意

- 成果物は必ずユーザーが見えるフォルダに置き、present_files で提示する
- テンプレートは `trip-report-creator` の規約に従う
  （既存の `*出張報告書.docx` / `*旅費精算.xlsx` をコピーして書き換えるため書式が完全に一致する）
- Plaud の録音名は日本語で内容が入っている（例「08-12 JSPS二国間共同セミナー申請に向けたキックオフ会議」）。
  期間で絞ったあと、**録音名で出張と無関係なものを外す**（所内の定例会議などが混ざる）
